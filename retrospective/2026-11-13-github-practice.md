# 회고: GitHub 프로필과 저장소 관리 실습

## S — Situation (상황)

GitHub를 단순히 코드를 올리는 저장소로 생각했지만, 프로필 README와 문서 작성 방식에 따라 학습 내용과 프로젝트 경험을 전달하는 포트폴리오가 될 수 있다는 점을 학습했다. 이번 특강에서는 GitHub 프로필 README 작성, Markdown 문법, Git 명령어, 저장소 관리의 기본 개념을 다뤘다.

## T — Task (과제)

배운 내용을 단순히 따라 하는 데서 끝내지 않고, 다른 사람이 읽기 쉬운 형태로 정보를 정리하는 방법과 Git을 이용해 변경 이력을 관리하는 기본 흐름을 이해하는 것이 목표였다.

## A — Action (행동)

- 프로필 README에 어떤 정보를 배치하면 좋을지 구성 요소를 살펴봤다.
- Markdown 제목, 목록, 강조, 링크, 코드 블록 등의 문법을 정리했다.
- `init`, `clone`, `status`, `add`, `commit`, `push`, `pull` 등 기본 명령어의 역할을 확인했다.
- 저장소에서 작업한 내용을 스테이징하고 커밋한 뒤 원격 저장소에 반영하는 흐름을 정리했다.
- 문서를 작성할 때 제목과 소제목을 구분하고, 표와 목록을 사용하면 내용을 빠르게 파악할 수 있다는 점을 확인했다.

## R — Result (결과 및 배운 점)

GitHub 프로필 README는 단순한 소개 글이 아니라 나의 역량과 학습 방향을 보여주는 첫 화면이라는 점을 이해했다. Markdown은 문서를 일관된 구조로 표현하는 데 유용하고, Git은 변경 사항을 단계별로 기록하고 공유하는 데 필요하다.

앞으로는 실습 결과를 저장소에 정리할 때 파일명과 폴더 구조를 일관되게 유지하고, 커밋 메시지에 변경 목적을 명확히 남기겠다. 프로필 README도 학습과 프로젝트가 추가될 때마다 갱신해 성장 과정을 보여주는 포트폴리오로 관리할 계획이다.

## 다음에 개선할 점

- 명령어를 외우는 것보다 직접 실행하고 결과를 확인하는 연습을 늘린다.
- README를 작성한 뒤 GitHub 화면에서 실제 렌더링을 확인한다.
- 작업 단위를 작게 나누고, 각 작업의 목적이 드러나는 커밋 메시지를 작성한다.
