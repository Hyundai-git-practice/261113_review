# TIL: GitHub 프로필 README, Markdown, Git 명령어와 저장소 관리

## Why — 왜 배웠는가?

GitHub는 코드를 저장하는 공간을 넘어 학습 과정과 프로젝트 결과물을 정리하고 공유하는 포트폴리오 공간이다. 다른 사람이 저장소를 방문했을 때 나를 이해하고 프로젝트를 빠르게 파악할 수 있도록 프로필 README와 저장소 문서를 작성하는 방법을 익힐 필요가 있었다.

또한 협업 과정에서 변경 이력을 안전하게 관리하고 다른 사람의 작업과 충돌하지 않도록 Git의 기본 흐름을 이해하는 것이 중요하다.

## What — 무엇을 배웠는가?

### 1. GitHub 프로필 README

- GitHub 사용자명과 동일한 이름의 저장소를 생성하면 프로필 상단에 표시되는 README를 작성할 수 있다.
- 자기소개, 기술 스택, 학습 기록, 프로젝트, 연락처 등을 구조화해 보여줄 수 있다.
- 방문자가 핵심 정보를 빠르게 파악하도록 간결한 문장과 일관된 구성을 사용하는 것이 좋다.
- 이미지, 배지, 링크 등을 활용할 수 있지만 정보 전달을 방해할 정도로 많이 사용하지 않는다.

### 2. Markdown 문법

| 문법 | 작성 예시 | 결과 |
|---|---|---|
| 제목 | `# 제목` | 큰 제목 |
| 소제목 | `## 소제목` | 하위 제목 |
| 굵게 | `**강조**` | **강조** |
| 기울임 | `*기울임*` | *기울임* |
| 목록 | `- 항목` | 글머리 목록 |
| 번호 목록 | `1. 항목` | 순서 목록 |
| 링크 | `[GitHub](https://github.com)` | 링크 |
| 이미지 | `![설명](이미지주소)` | 이미지 |
| 인라인 코드 | `\`코드\`` | 코드 강조 |
| 코드 블록 | `\`\`언어`로 시작 | 코드 영역 |
| 인용 | `> 인용문` | 인용 영역 |
| 구분선 | `---` | 구분선 |

### 3. Git 기본 명령어

| 명령어 | 역할 |
|---|---|
| `git init` | 현재 폴더를 Git 저장소로 초기화 |
| `git clone <URL>` | 원격 저장소를 로컬로 복제 |
| `git status` | 파일 변경 상태 확인 |
| `git add <파일>` | 변경 파일을 스테이징 영역에 추가 |
| `git add .` | 현재 디렉터리의 변경 사항 추가 |
| `git commit -m "메시지"` | 변경 사항을 커밋으로 기록 |
| `git log` | 커밋 이력 확인 |
| `git branch` | 브랜치 목록 확인 |
| `git switch <브랜치>` | 브랜치 전환 |
| `git switch -c <브랜치>` | 브랜치 생성 후 전환 |
| `git pull` | 원격 변경 사항을 가져와 현재 브랜치에 통합 |
| `git push` | 로컬 커밋을 원격 저장소에 반영 |

### 4. 저장소 관리 기본 흐름

1. 저장소를 생성하거나 `git clone`으로 복제한다.
2. 작업할 브랜치를 생성하거나 이동한다.
3. 파일을 수정하고 `git status`로 변경 사항을 확인한다.
4. 필요한 파일을 `git add`로 스테이징한다.
5. `git commit`으로 변경 이력을 기록한다.
6. `git push`로 원격 저장소에 공유한다.
7. 협업 시 다른 사람의 변경 사항을 `git pull`로 반영하고 충돌 여부를 확인한다.

## How — 어떻게 활용할 것인가?

- GitHub 프로필 README를 자기소개, 기술 역량, 프로젝트, 학습 기록 중심으로 구성한다.
- Markdown으로 문서의 제목과 목록 구조를 명확하게 만든다.
- 작업 전후 `git status`를 확인하고, 의미 있는 단위로 커밋한다.
- 커밋 메시지는 변경 목적이 드러나도록 작성한다.
- 여러 작업을 동시에 진행할 때는 목적에 맞는 브랜치를 분리해 관리한다.
- README와 TIL을 꾸준히 업데이트해 학습 과정이 포트폴리오로 이어지도록 한다.

## 오늘의 핵심 정리

GitHub는 결과물을 공개하는 공간이면서 작업 과정을 기록하는 공간이다. Markdown은 그 내용을 읽기 쉽게 구조화하고, Git은 변경 이력을 안전하게 관리하는 도구라는 점을 기억하자.
